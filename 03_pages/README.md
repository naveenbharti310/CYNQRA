# Browser pages

Ten single file reports. Nothing to install, no server, no build step. Double click any
file and it opens in a browser. They were built this way because the founder works from a
browser and has nothing installed, and they are kept in the handover because they are the
fastest way for a new person to see what happened.

Read them in this order.

| File | What it shows |
| --- | --- |
| `cynqra-run-002.html` | The run board. Ten days, four workers, every break, the measured numbers |
| `cynqra-run-002-close.html` | The closing verdict on run 002, which was NO-GO on M2 |
| `cynqra-run-002-audit.html` | The audit of that run, including which claimed results were thrown out |
| `cynqra-g0-session.html` | The G0 ratification session as it was put to the founder, thirty decisions with options |
| `cynqra-g0-results.html` | What the founder actually decided, including Hybrid for D-22 |
| `cynqra-s3-memo.html` | The S3 verification result, 9 of 10, and the one defect it missed |
| `cynqra-m1-two-weeks.html` | The current two week plan, 25 August to 8 September |
| `cynqra-s1-paste-pack.html` | The ten S1 items with copy buttons, for running S1 by hand without an API key |
| `cynqra-d22-counsel.html` | The draft letter to counsel about the immutable log versus erasure duty |
| `candidate-tracker-app.html` | The candidate tracker built during the run. This is the test fixture, not the product |

A note on the last one, because it has caused confusion before. The candidate tracker is a
chew toy. It exists so a fake organization had something real to build and so verification
had something real to check. Cynqra is the organization layer, not the tracker.

These pages are snapshots. When a number changes, the source of truth is the report file
in `02_harness/`, not the page.
